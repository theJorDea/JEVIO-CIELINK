# CIELINK · Подключение домашнего интернета за один звонок

Проект команды JEVIO-CIELINK для [SkyNet Signal, кейс №2](https://aiskyhack.itmobc.ru/team-6941db672243d5f01d53/). **Статус: базовый ASR-компонент в разработке.** Здесь план реализации и приёмки, а не описание запущенного телефонного сервиса. Публичного тестового номера и замеров пока нет. Внутренние API SkyNet не предполагаются доступными.

**Для клиента:** позвонить с обычного телефона, узнать условия именно для своего дома, поправить адрес или бюджет, получить номер согласованной заявки либо подтверждение проверки дома. **Для SkyNet:** понять по записи, что услышал клиент, какие условия применились и что попало в CRM. Перед выпуском новой акции — проверить на тех же ситуациях, какие обещания изменятся.

> «Дом восемнадцать, корпус один… Нет, второй. И до девятисот — это после скидки тоже». Агент прекращает речь, сохраняет бюджет, отбрасывает проверку первого корпуса. Если данных о втором нет, предлагает проверить **второй корпус**, а не подключить первый. «Да, я слышу» не считается заказом.

## Функциональность по этапам

| Этап | Возможности |
|---|---|
| Основа | Настоящий входящий номер → SIP → русская речь; проверка дома; 1–2 доступных тарифа с ценой сейчас и после акции; согласие и номер заявки. Отказ, неизвестный адрес и сбой — разные исходы. |
| Отличие проекта | Speculative orchestrator запускает проверки, пока человек говорит. Перебивание останавливает озвучку; поправка отменяет только зависимые результаты. Три режима сравнения на одних входах. |
| Рабочее место компании | Запись по ролям, транскрипция, таймкоды обещаний, сопоставление с версией каталога и CRM. Из эпизода — тест; из черновика акции — отчёт об изменениях до публикации. |
| После демо | Тёплый перевод, выбор корпуса по одноразовой ссылке, подтверждённое окно монтажа при наличии расписания, аналитика неизвестного покрытия. Гипотезы и условия запуска — в roadmap. |

## Данные и запуск

Цены и ограничения — с [сайта SkyNet](https://skynet.ru/internet/tarify/), с URL и датой просмотра; доступность для конкретного дома, клиенты, очереди и заявки в демо — **учебные**. Реальных клиентов, телефонные номера абонентов, аудио без разрешения и ключи провайдеров в Git не добавляем.

Телефонный релиз должен дополнить этот раздел проверенными командами установки и запуска, версиями зависимостей, примером настроек без секретов, инструкциями для тестового номера и локального повтора сценария без платного звонка. Сейчас репозиторий содержит исполняемую основу ASR, но ещё не готовый телефонный сервис или сдачу на хакатон.

## Основа потокового ASR

В репозитории есть минимальный Python-адаптер для `GigaAM-v4 RNN-T`. Он загружает веса один раз, создаёт отдельное состояние распознавания на звонок и предоставляет CLI для проверки локального аудиофайла. Для разработки нужны Python 3.10+, `ffmpeg` в `PATH` и PyTorch, подходящий к CPU/GPU машины.

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[asr,voice-test,test]"
pytest
cielink-asr .\sample.wav --context-ms 320
cielink-echo
```

При первом запуске GigaAM скачивает checkpoint и tokenizer в свой пользовательский cache. CLI принимает аудио, которое может прочитать `ffmpeg`, приводит его к mono 16 kHz и обрабатывает чанками. Для будущего SIP-подключения `ASRSession.feed()` ожидает одномерный `torch.float32` waveform mono 16 kHz; декодирование телефонного кодека и ресемплинг должны происходить в аудиовходе до вызова адаптера. Подробности интерфейса и ограничения — в [архитектуре](docs/architecture.md).

`cielink-echo` запускает локальный push-to-talk тест. Нажмите Enter, произнесите фразу, нажмите Enter ещё раз и дождитесь воспроизведения распознанного текста. По умолчанию используется OmniVoice на CUDA с одним повторно используемым эталоном мужского взрослого голоса; Kokoro-RU и Silero V5 остаются доступны через `--tts-engine kokoro` и `--tts-engine silero`. Модель загружается при первом запуске в cache Hugging Face. Веса OmniVoice распространяются по CC-BY-NC, поэтому этот выбор предназначен для локальной оценки, а не коммерческого запуска. Тестовая запись остаётся в памяти процесса и не сохраняется в файл.

`cielink-voice-server` и standalone live-режим используют один публичный адресный каталог SkyNet и хранят выбранный тип объекта и адрес в пределах сессии. Поиск учитывает числительные, сокращения и падежные формы улиц, поправка корпуса не должна подменяться похожим номером дома, а независимые совпадения приводят к уточнению. Агент различает новое подключение и обращение действующего абонента. Каталог помогает найти точную запись, но не является подтверждённым API проверки подключения, а отсутствие дома не означает отказ. Отправка заявки и реальный перевод в поддержку пока не реализованы.

Для голосового диалога используйте локальный сервер и CLI в двух PowerShell окнах:

```powershell
cielink-voice-server
cielink-echo --live
```

Режим показывает распознанный текст во время речи, завершает реплику после паузы и озвучивает ответ. Во время озвучивания микрофон продолжает работать: новая реплика прерывает ответ и отправляется в распознавание. Для теста используйте наушники, чтобы звук динамиков не срабатывал как перебивание. По умолчанию пауза составляет 800 мс, порог голосовой активности — RMS 0.012. Настройте их параметрами `--silence-ms` и `--threshold`, например `cielink-echo --live --silence-ms 1000 --threshold 0.008`.

Чтобы автономный агент уточнял тип объекта и искал названные улицу и дом в каталоге SkyNet, запустите:

```powershell
cielink-echo --live --standalone
```

Для этого режима задайте `CIELINK_LLM_PROVIDER` и модель Ollama либо API-ключ OpenAI-compatible. Каталог загружается с сайта SkyNet при первом запуске, затем обновляется раз в сутки и хранится в пользовательском cache. Агент сохраняет тип объекта и последние реплики текущего разговора. Найденный статус озвучивается как справочная запись каталога, не как гарантия подключения; отсутствующее или неоднозначное совпадение не трактуется как отказ. `--standalone` позволяет сравнить прямой CLI-путь с WebSocket-сервером.

Live-режим по умолчанию подключается к локальному серверу консультаций на `ws://127.0.0.1:8000/ws/voice`:

```powershell
cielink-echo --live
```

В этом режиме GigaAM распознаёт микрофон, а `cielink-voice-server` ведёт консультацию и хранит адрес между репликами. LLM формулирует ответ на основе найденной записи каталога. Для отдельного прямого CLI-пути используйте `cielink-echo --live --standalone`. Адрес сервера можно заменить параметром `--voice-url` или переменной `CIELINK_VOICE_URL`.

Ollama удерживает модель загруженной 10 минут после последней реплики, чтобы не повторять холодную загрузку в середине теста. Запрос использует контекст 4096 токенов, достаточный для короткого голосового хода и освобождающий видеопамять для GigaAM. Настройки меняются переменными `CIELINK_LLM_KEEP_ALIVE` и `CIELINK_LLM_CONTEXT`.

Порядок локальных прогонов «подключение» и «поправка корпуса» — в [инструкции #15](docs/browser-trials.md). Требования к тестовому номеру, SIP-маршруту, оператору и откату — в [инструкции #16](telephony/README.md).

### LLM в голосовом тесте

Без LLM `cielink-echo` повторяет распознанную фразу. Для локального режима установите [Ollama](https://ollama.com/), загрузите модель и задайте переменные в PowerShell:

```powershell
ollama pull qwen3:4b
$env:CIELINK_LLM_PROVIDER = "ollama"
$env:CIELINK_LLM_MODEL = "qwen3:4b"
$env:CIELINK_LLM_TIMEOUT = "120"
cielink-echo
```

Для облачного OpenAI API задайте ключ и модель:

```powershell
$env:CIELINK_LLM_PROVIDER = "openai-compatible"
$env:CIELINK_LLM_API_KEY = "..."
$env:CIELINK_LLM_MODEL = "gpt-4o-mini"
cielink-echo
```

По умолчанию облачный режим использует `https://api.openai.com/v1`. Для другого OpenAI-compatible сервера укажите `$env:CIELINK_LLM_BASE_URL`, например `https://api.example.com/v1`. Ключ читается только из окружения и не сохраняется в репозитории. Фраза распознанной речи отправляется выбранному backend-у. В тестовом системном промпте запрещено выдумывать цены, покрытие и оформленные заявки. В рабочем сценарии факты и действия должны оставаться за проверяемой бизнес-логикой CIELINK.
