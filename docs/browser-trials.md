# Локальные голосовые прогоны

Этот протокол предназначен для двух учебных разговоров с добровольцем: подключение и поправка корпуса. Он не требует номера или АТС. Используются локальные GigaAM, Ollama и OmniVoice через `cielink-echo --live`. Для локального сравнения Kokoro запустите команду с `--tts-engine kokoro`.

## Готовность

- Участник использует микрофон и наушники. До начала объяснить, что голосовой ответ формирует локальная модель и что запись будет храниться только локально.
- Использовать только вымышленные адреса и данные. Не публиковать запись, имя участника и системные логи.
- Установлены зависимости проекта и локальная LLM. Проверить её отдельным запуском до приглашения участника.
- Выбрать локальное средство записи, которое сохраняет микрофон и звук ответа раздельно. Проверить оба канала коротким пробным фрагментом и путь хранения.

```powershell
$env:CIELINK_LLM_PROVIDER = "ollama"
$env:CIELINK_LLM_MODEL = "hf.co/XHToken/Spark-X2.6-4B-GGUF:Q4_K_M"
$env:CIELINK_LLM_TIMEOUT = "120"
cielink-echo --live
```

При необходимости настройте обнаружение паузы и уровень микрофона, например `--silence-ms 800 --threshold 0.008`. Наушники обязательны для проверки перебивания без срабатывания на звук ответа.

## Порядок

1. Запустить локальную запись обеих дорожек и убедиться, что файлы создаются в выбранной папке.
2. Провести разговор «Подключение». Попросить участника уточнить адрес, выслушать ответ и один раз перебить озвучивание. Использовать только заранее подготовленные учебные условия.
3. Остановить запись и проверить, что слышны микрофон и ответ. Сохранить файл локально под случайным идентификатором, например `trial-01`.
4. Начать отдельную запись и провести разговор «Поправка корпуса». Сначала назвать учебный адрес с одним корпусом, затем поправить его на другой. Перебить ответ поправкой и проверить, что последующая реплика распознана.
5. Остановить запись, проверить обе дорожки и сохранить локально как `trial-02`.
6. Удалить неудачные тестовые фрагменты и временные экспорты. Зафиксировать результаты без имени и контактов участника.

## Карточка результата

Для каждого прогона заполнить:

| Поле | Значение |
|---|---|
| Случайный ID | `trial-01` или `trial-02` |
| Сценарий | Подключение / поправка корпуса |
| Файлы двух дорожек проверены | Да / нет |
| Перебивание остановило TTS | Да / нет / не проверено |
| Исправленная фраза распознана | Да / нет / не применимо |
| Ошибка и таймкод | Краткая заметка |
| Удаление локальной записи проверено | Да / нет |

## Текущие ограничения

В репозитории пока нет браузерного интерфейса и встроенной записи дорожек. `cielink-echo --live` работает как локальный консольный тест и поддерживает прерывание ответа, но сам не сохраняет аудио. Перед формальным прогоном нужно проверить выбранное локальное средство записи; если оно не умеет сохранять микрофон и ответ раздельно, тест не подтверждает требование двух дорожек. Не добавлять записи добровольца в Git.
