# Roadmap · от входящего звонка до пилота

**Правило планирования:** защищаем кейс №2, не строим колл-центр целиком. P0 — обязательный результат; P1 — техническое отличие, которое показываем после зелёного P0; P2 — эксперимент или пилот. Это план, чекбоксы не означают готовность. Роли ниже можно совмещать: **Voice** — телефония и речь, **Rules** — адреса и тарифы, **Ops** — операции и записи, **QA** — полигон и защита.

## Спринт хакатона

| Когда / кто | Что сделать | Готово, если… |
|---|---|---|
| 27 ноября, старт · Voice · P0 | Поднять настоящий входящий номер и SIP-маршрут; потоковые STT/TTS, перебивание, запись двух сторон. | С мобильного слышен ответ; на «стоп» бот замолкает; обе дорожки доступны для контрольного звонка. Если нет номера, немедленно эскалировать капитану, не выдавать браузер за телефон. |
| Параллельно · Rules + QA · P0 | Снимок официальных условий, небольшой каталог, учебные дома: доступный, неизвестный, подтверждённо вне сети и два похожих. Отдельно — сбой сервиса. Зафиксировать эталонные исходы до реализации. | Для каждого сценария есть точный дом, применимость акции, допустимый итог и основание цены; условия без источника не озвучиваются как факт. |
| Первая сквозная сборка · Ops + Voice · P0 | Из свободной речи выбрать 1–2 предложения, объяснить разницу, подтвердить актуальные поля и записать результат. Отказ и передача в учебную очередь — полноценные исходы. | Живой абонент получил номер существующей заявки. При смене на неизвестный корпус в очереди только запрос на проверку. Двойное «да» не создаёт дубль. |
| 28 ноября, первая половина · Voice + Rules · P1 | Версии полей, граф зависимостей, опережающие чтения по устойчивому partial, отмена устаревших ответов, учёт прерванной озвучки; переключатель A/B/C. | Поздний результат по первому корпусу не попадает ни в звук, ни в CRM; новая сумма не заставляет переспрашивать адрес. Есть логи с причинами запуска и отмены. |
| Параллельно · Ops · P1 | Поднять рабочее место: список звонков, исход, запись по ролям, транскрипт, кликабельный таймкод, карточка заявки и версия условий. Асинхронная тяжёлая модель извлекает обещания. | Из замечания можно перейти к звуку и проверить его по каталогу и CRM. Оператор подтверждает или снимает замечание. Отсутствие записи отмечено явно. |
| 28 ноября, вторая половина · Rules + QA · P1 | Один разобранный эпизод превратить в обезличенный регрессионный тест. Сравнить утверждённый каталог и черновик акции на тех же фактах. | Видно, кому и **почему** изменили предложение, кому изменение не помогло. Историческая заявка не переписана. Предсказание не выдано за запись нового звонка. |
| До заморозки · QA + Voice · P1 | Прогнать три режима на одном наборе. Несколько отдельных мобильных звонков; проверить счётчик лишних запросов, задержку на телефоне, перебивания и правильность итогов. | Таблица содержит число наблюдений, режим, условия, ошибки и фактические замеры, а не обещанный выигрыш. Нулевой выигрыш тоже результат. |
| Перед 10:00 МСК 29 ноября · капитан · P0 | Заморозить рабочую версию, записать звонок, собрать презентацию по шаблону, проверить чистый запуск и публичный доступ без авторизации. | Видео вложено в презентацию и приложено отдельно; каждый файл ≤20 МБ. README позволяет повторить демо. Защита укладывается в 3 минуты, ещё 3 — вопросы. |

**Если отстаём:** режем карту, SMS, монтаж и полное редактирование акций; для P1 оставляем один сценарий поправки и одну пару версий каталога. Не режем настоящий номер, согласие, оба результата кейса, честную стоимость и проверку того, что реально записалось. Этапы пилота — не обещание успеть к защите.

## Очередь экспериментов и внедрения

| Приоритет / гипотеза | Минимальный эксперимент | Результат для решения |
|---|---|---|
| P1 · Обоснованная цена | Подать конфликт «от 750» / «от 850» из двух публичных страниц и ограничение «2 000 сегодня, 900 потом». Раздельно учесть аванс, регулярные платежи, срок акции, оборудование. | Никакой произвольной цены; расчёт по утверждённой версии или уточнение. [Правила](docs/architecture.md). |
| P1 · [Адрес на слух: статьи и эксперимент](docs/address-asr.md) | Сравнить базовую STT, поиск кандидатов (выборка ГАР/ФИАС + `pg_trgm`) и контекстный словарь. Включить «18/2», «18 корпус 2», литеру и дом вне сети. | Exact match полного дома, ложные уверенные совпадения, число уточнений; агент спрашивает различающий признак. |
| P2 · Локальный ASR | Сопоставить SpeechKit Streaming и T-one на одинаковой телефонной записи. Отдельно проверить ранний декодер T-one, а не считать 300-мс блок готовым partial-текстом. | Время до устойчивого адреса, ошибка корпуса, ресурсы и стоимость. Если раннего текста нет — кандидат для постанализа, не блокер звонка. |
| P2 · Слушать, не перебивая | Сравнить VAD и контекстное определение перебивания на «угу», кашле, «стоп» и длинной паузе. Затем сквозную speech-to-speech модель и каскад с одинаковыми правилами и инструментами. | Ложные остановки, время до тишины, правильность денег и заявок, слепая оценка естественности, стоимость. Учитывать облачные зависимости. |
| P2 · Полезный следующий вопрос | Вместо анкеты проверить, меняет ли ответ допустимые предложения или следующее действие. | Меньше вопросов при не худшем подборе; согласие и обязательные сведения пропускать нельзя. |
| P1 · [Один звонок — три свидетельства](docs/company-cases.md) | Учебный сервис возвращает варианты зданий. Сохраняем версию условий для речи, опционального экрана и действия в CRM. Для демо достаточно одной тестовой карточки, доставка SMS не обязательна. | После поправки корпуса устаревшее подтверждение отклоняется сервером. В разборе видны фрагмент записи, версия показанной карточки (или «не открыта») и реальный тип операции. |
| P2 · Выбор на экране | При повторной неоднозначности, с разрешения, послать одноразовую ссылку с двумя домами; событие выбора возвращается в текущий звонок. | Выбор не переносится в чужую или завершённую сессию; ссылка истекает, без неё голосовой путь работает. |
| P2 · Тёплый перевод | Сначала передать специалисту резюме и открытый вопрос. Проверить занятую очередь и предложить обратный звонок с согласия. | Доля успешных соединений и повторного диктования адреса; учебная очередь не изображается как живой сотрудник. |
| P2 · Монтаж за один звонок | Запросить у SkyNet владельца расписания. На учебном адаптере предложить два окна, воспроизвести конкурирующую бронь и проверить подтверждение. Дальше — маршруты бригад и временные окна (OR-Tools). | Без ID брони сохраняется только пожелание. В пилоте — обратные звонки на состоявшийся монтаж, переносы, успешные выезды. |
| P2 · Спрос и пробелы в покрытии | Связать обезличенные обращения по дому с ответом инженера и фактом подключения; при объёме — кластеризация PostGIS. | Различимы устаревшая база, подтверждённое отсутствие и сбой. Спрос звонивших не выдаётся за спрос района. |
| P2 · Голосовой полигон | Управляемый абонент отвечает на изменившийся вопрос; минимальные пары в духе τ-Voice. Сохранённый тест всегда проверяет конечное состояние. | Ошибки воспроизводятся; набор для оценки отделён от разработки; есть живой контроль с мобильного. |
| P2 · Предохранитель выпуска (новая гипотеза) | Для черновика определить запрет выпуска: хотя бы одна заявка без согласия или неверная подтверждённая сумма. Владелец разбирает эпизод, а не усреднённый балл. | Тестовый «плохой релиз» заблокирован; исправленный проходит тот же набор. Действующую ветку АТС можно вернуть оператору. |

## Что спросить у SkyNet до пилота

Кто утверждает коммерческие условия при конфликте? Какие статусы возвращает покрытие, как связать их с ID дома? Может ли CRM найти операцию по внешнему ключу? Как маршрутизировать перевод и кому принадлежат окна монтажа? Где разрешено обрабатывать записи и кто отвечает за удаление? Без ответов оставляем подписанные учебные адаптеры. Порядок внедрения: **исторические данные → рекомендации рядом с оператором → одна входящая ветка с возможностью отката**. Критерии перехода и измерения — в [плане проверки](docs/validation.md).
